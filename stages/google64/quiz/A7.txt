Q1. 退職した社員がマイドライブに置いていたプロジェクト資料が、アカウント削除とともに消えかけました。今後これを防ぐ根本策はどれでしょうか？
1. ファイルをチームの持ち物になる「共有ドライブ」に置き、担当者が去っても残るようにする ← 正解
2. 退職者のアカウントを削除せず、無効化したまま長期間保持しておく
3. 重要ファイルは退職前に、各メンバーのマイドライブへコピーして配っておく
4. 退職者のマイドライブを別のメンバーへ「所有者変更」して引き継ぐ
解説：マイドライブは個人の畑、共有ドライブはみんなの畑なのじゃ。アカウントを塩漬けにしたりコピーを配ったりは、その場しのぎで版が散らばる——はじめからチームの畑に植えておけば、誰が去っても実りは残るのう。ね、兄者？「うむ」

Q2. マイドライブのファイルと共有ドライブのファイルの「所有権」の違いとして、正しいものはどれでしょうか？
1. どちらも作成した個人が永久に所有者で、フォルダを移しても変わらない
2. マイドライブは個人が所有者、共有ドライブはチーム(組織)が所有者になる ← 正解
3. 共有ドライブに入れると、所有者が自動でその管理者個人に変わる
4. マイドライブのファイルは、共有した瞬間に相手が所有者になる
解説：マイドライブの持ち主はあくまで作った本人、共有ドライブに入れた品はチーム(組織)の持ち物になるのじゃ。だから所有者が退職しても組織の資産として残る——この所有権の移り変わりが、消えない安心の正体よのう。 共有ドライブを使える契約と、組織の作成許可も確認するのじゃ。

Q3. 共有ドライブの作り方として推奨される運用はどれでしょうか？
1. 会社に1つだけ巨大な共有ドライブを作り、全部門を詰め込む
2. 社員1人につき1つずつ、専用の共有ドライブを作る
3. プロジェクトや部門ごとに共有ドライブを分け、必要なメンバーに権限を付与する ← 正解
4. 案件ごとに毎回新しく作り、終わったものも消さずに全部残し続ける
解説：プロジェクトや部門ごとに蔵を建て、入る者を決めるのが良い運びじゃ。1つの大蔵に全部詰めると誰が何を見られるか分からなくなり、個人ごとや作りっぱなしでは共有ドライブの意味が薄れる——単位を揃えるのが肝よのう。

Q4. 共有ドライブにメンバーを追加します。「管理者」「コンテンツ管理者」「編集者」「閲覧者」がある中で、実務的に適切な考え方はどれでしょうか？
1. 誰も困らないよう、全員に管理者権限を渡す
2. 迷ったら全員を閲覧者にし、編集はすべて管理者が代行する
3. 社外の人にはコンテンツ管理者以上を渡すのが礼儀
4. 作業に必要なメンバーへ、役割に応じた権限を過不足なく付与する ← 正解
解説：必要な人に必要な役割だけ、が権限の作法じゃ。全員を管理者にすれば蔵の鍵を村中に配るようなもの、逆に全員閲覧者では作業が回らん——役割に合わせて過不足なく、が丁度よいのう。

Q5. 共有ドライブに社外の協力会社メンバーを一時的に招く必要があります。プロジェクト終了後まで見据えた安全な運用はどれでしょうか？
1. 作業に必要な範囲の権限を付与し、プロジェクト終了時に権限を解除する ← 正解
2. 終了後も権限はそのまま残しておく(また頼むかもしれないから)
3. 社外メンバーには管理者権限を渡し、後片付けも任せる
4. 社外共有は手間なので、全ファイルを一般公開リンクで渡す
解説：必要な範囲だけ招き、用が済んだら鍵を返してもらうのが正しい道じゃ。招いたなら見送りまでが作法——権限を残しっぱなしにすると、忘れた頃に漏れの穴になるのう。ね、兄者？「うむ」
