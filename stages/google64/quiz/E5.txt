【E5】IMPORTRANGEによるシート間連携：権限を分離した安全な集計環境の構築 - クイズ（サイト実装分）

出典：stages/google64/data/quests/E.js の E5
サイト版：quest.html?id=E5

Q1. IMPORTRANGE関数の正しい書き方はどれ？
1. =IMPORTRANGE("範囲", "シートURL")
2. =IMPORTRANGE(シート名, 行番号, 列番号)
3. =IMPORTRANGE("シートURL", "範囲") ← 正解
4. =IMPORTRANGE("ファイル名") だけでよい
解説：第1引数に元シートのURL、第2引数に欲しい範囲だ、クルックー。「どの書物の・どの頁か」を告げる作法なのだよ。

Q2. IMPORTRANGEを初めて使ったところ「アクセスを許可」の確認ダイアログが出た。正しい対応は？
1. ウイルスの可能性があるので、すぐにシートを閉じる
2. 参照元と参照先の共有範囲を確認したうえで「アクセスを許可」する ← 正解
3. 何度も再読み込みを繰り返してダイアログを消す
4. 元シートを削除してから作り直す
解説：接続を許可すると、参照先の編集者は元ファイルの別の範囲も取り込めるのだ。関所を開く前に、誰に編集の鍵を渡しているか確かめたまえ。

Q3. 「元の台帳は絶対に触らせたくないが、集計結果は部署の面々に見せたい」。適切な構成は？
1. 台帳シート本体を、全員に編集権限付きで共有する
2. 台帳を毎回PDF化して、メールで配る
3. 全員分の台帳のコピーを個別に作って配布する
4. 閲覧だけの集計表を共有し、機密がある場合は公開可能な集計値だけの別ファイルを参照元にする ← 正解
解説：参照先の編集者は元ファイルの他の範囲も読めるのだ、クルックー。機密を守るなら、取り込み元にも公開可能な集計値だけを置く。範囲指定だけを壁と思ってはならぬ。

Q4. IMPORTRANGEを入れたセルが「#REF!」となり赤く表示された。まず疑うべき原因は？
1. パソコン本体の物理的な故障
2. Googleの大規模障害でしか起きない現象
3. アクセス許可が未承認、またはURL・範囲の指定ミス ← 正解
4. 関数名の綴りだけが原因で、URLは無関係
解説：#REF! の赤旗が立てば、まず許可の未承認かURL・範囲の綴りを疑うのだ、クルックー。関所と番地、この二つを検めれば大方は解けるのだよ。

Q5. IMPORTRANGEによる権限分離が、実務にもたらす一番の利点はどれ？
1. 元データの編集を分けられるが、取り込み先の閲覧・編集権限も設計する必要がある ← 正解
2. 元シートが自動で暗号化され、URLが無効になる
3. 参照先のデータを、自由に書き換えられるようになる
4. 共有する相手が増えるほど、シートの動作が軽くなる
解説：原本を直接書き換えずに集計できる一方、取り込み先の共有設計は欠かせぬ。何を見せるか、誰が式を変えられるかを決めるのだ。
