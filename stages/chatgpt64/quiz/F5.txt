【F5】エラー対処とデバッグの指示出し - クイズ（サイト実装分）

Q1. エラーが出たとき、F5で学ぶ基本の対処はどれ？
1. エラーメッセージをそのままAIに渡して直させる ← 正解
2. エラーの意味を辞書で調べてから対応する
3. パソコンを再起動して様子を見る
4. エラーが消えるまで同じ操作を繰り返す
解説：エラー文はそのままAIに渡すのが基本の型。「そのまま渡して直させる」を覚えれば、エラーで止まらない人になれる。

Q2. F5のプロンプト例に含まれる「撤退条件」はどれ？
1. 「エラーが直るまで何日でも試し続けて」
2. 「1回試してダメならすぐあきらめて」
3. 「3回試してダメなら、状況を整理して私に相談して」 ← 正解
4. 「ダメだったことは報告しなくていい」
解説：「3回試してダメなら相談して」の撤退条件が効く。無限に試させず、1回で諦めもしない。区切りを決めるのが監督の仕事。

Q3. デバッグを頼むとき、あわせて報告させるとよいのはどれ？
1. エラーが出た時刻と天気
2. 何を試して何がダメだったか、順を追った報告 ← 正解
3. AIの感想と反省文
4. エラーの発生回数だけ
解説：「試したことと結果を順に報告して」と頼む。次の一手を一緒に考えられる。

Q4. 「エラー文を見て自分で悩んでしまう」つまずきへの考え方はどれ？
1. エラー文を全部暗記して次に備える
2. エラーが出た作業はもうやらないと決める
3. 悩んだ時間だけ実力がつくのでじっくり悩む
4. エラー文は読まずにまず貼る。読むのはAIの仕事 ← 正解
解説：エラー文は読まずにまず貼る、読むのはAIの仕事。貼れば数秒で原因を調べてくれる。

Q5. F5の実践課題はどれ？
1. わざとエラーを100回出して耐性をつける
2. 実際に出たエラーを1つ、Codexに自己解決させる ← 正解
3. エラーメッセージの英単語帳を作る
4. エラーが出ないように作業自体を減らす
解説：実際のエラーを1つCodexに自己解決させる。一度体験すると「はいはい、貼ればいいのね」と落ち着ける。
