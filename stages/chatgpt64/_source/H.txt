# H1 /goalで長時間の無監督自律作業

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: /goalコマンドの使い方として正しいのはどれ？
- 正解: 達成したいゴールと制約を渡し、達成するまでAIに試行錯誤を任せる
- 解説: ホウ、/goalは「ゴールだけを渡す」コマンドだよ。達成するまでAIが自分で試行錯誤を続けてくれる。指示を出す人から、仕組みを持つ人への入り口だね。
- よくある誤解（誤り）: 1つの操作が終わるたびに、次の操作を細かく指示する / AIに質問を投げて、答えを1つ返してもらう / PCの設定画面を開いて動作速度を上げる

### 要点2
- 問い: プロンプト例に沿った/goalの渡し方はどれ？
- 正解: 「/goal このフォルダの全資料を分類・リネーム・目次化し、完了報告書を作ること。制約：削除は禁止、迷ったら保留フォルダへ」
- 解説: ゴールと制約をひとまとめに渡すのがコツだよ。「削除は禁止、迷ったら保留フォルダへ」と逃げ道まで示しておく。これで夜のあいだも安心して任せられるね。
- よくある誤解（誤り）: 「/goal なんとなくフォルダをいい感じにして」 / 「/goal 今から言う操作を1つずつ実行して」 / 「/goal 私が戻るまで何もせずに待機して」

### 要点3
- 問い: ゴールが曖昧でAIが暴走・空回りしてしまうとき、有効な対処はどれ？
- 正解: 「完了と言える条件」を数えられる形（〜がすべて〜の状態）で書く
- 解説: 夜道で迷うのは、行き先がぼんやりしているからだよ。「全ファイルがリネーム済みの状態」のように、数えられる形で完了条件を書いてごらん。ホウ、それだけで空回りはぐっと減るよ。
- よくある誤解（誤り）: AIの性能が上がるまで/goalの利用をやめる / ゴールを書かずに何度もやり直させる / 制約をすべて外して自由にやらせる

### 要点4
- 問い: H1がステージHの最初に置かれている理由はどれ？
- 正解: 無監督の自律作業という、このステージ全体の基本の型だから
- 解説: ステージHのテーマは「あなたが見ていない間もAIが働く」こと。その基本の型が/goalの目標完遂ループなんだよ。ここを覚えれば、あとのマスはこの型の応用だね。
- よくある誤解（誤り）: 一番短時間で終わる軽いマスだから / 他のマスとは無関係な独立した内容だから / スマホの設定だけで完結するから

### 要点5
- 問い: 制約に「削除は禁止」と入れておく意味はどれ？
- 正解: 無監督で走らせる間に、取り返しのつかない事故を防ぐため
- 解説: 見ていない間に任せるからこそ、先に安全な範囲を決めておくんだよ。削除のような戻れない操作は禁止し、迷ったら保留へ。静かな夜を守る知恵だね。
- よくある誤解（誤り）: AIの作業速度を上げるため / 削除を禁止すると料金が安くなるから / 報告書の文字数を減らすため

## 実践ミッション
小さめのゴール（例：特定フォルダ内の資料の分類と目次化）を「削除は禁止、迷ったら保留フォルダへ」などの制約つきで/goalに渡し、無監督で完遂させます。

- 提出する証拠: /goalに渡した指示文と、AIからの完了報告が分かるスクリーンショット。ファイル名や案件名に顧客名・社外秘が含まれる場合はマスクして共有していただいて構いません。

# H2 PLAN.mdで中長期計画を進める

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: PLAN.mdとはどんなものか、このマスに沿う説明はどれ？
- 正解: 数日〜数週間かかる仕事の計画を書き、AIと共有する「作戦地図」のファイル
- 解説: PLAN.mdは、長い仕事のための作戦地図だよ。人とAIが同じ地図を見て進めば、道に迷わない。長期戦にはまず地図、だね。
- よくある誤解（誤り）: AIの利用料金を記録する家計簿ファイル / AIとの雑談の履歴を保存するファイル / PCのバックアップ設定ファイル

### 要点2
- 問い: PLAN.mdに入れておく要素の組み合わせとして、プロンプト例に沿うのはどれ？
- 正解: フェーズ分け・各フェーズの完了条件・現在地のチェック欄
- 解説: 地図に要るのは、道のり（フェーズ）と、着いたと言える印（完了条件）と、いまどこか（現在地）だよ。この3つがあれば、何日空いても続きから歩けるね。
- よくある誤解（誤り）: 担当者の顔写真・座右の銘・好きな色 / パスワード・アカウント情報・支払い方法 / 会議の議事録・出席者リスト・弁当の注文数

### 要点3
- 問い: 毎回のセッションの始めにやることとして、このマスに沿うのはどれ？
- 正解: AIにPLAN.mdを読ませて、現在地を確認してから続きを進める
- 解説: 「毎回これを読んでから作業を始めて」と決めておくんだよ。AIが地図を開いて現在地を確かめてから歩き出す。ホウ、これが長期戦の型というものだね。
- よくある誤解（誤り）: 前回の会話をすべてコピーして貼り直す / 計画を毎回ゼロから作り直す / まず雑談をして場をあたためる

### 要点4
- 問い: 計画が実態とズレたまま放置されてしまう、というつまずきへの対処はどれ？
- 正解: 作業のたびに、AI自身にPLAN.mdを更新させる
- 解説: 地図は描いて終わりじゃなく、歩きながら描き足すものだよ。作業のたびにAI自身に更新させれば、鮮度が保たれる。計画の鮮度が、使い物になるかどうかの分かれ目だね。
- よくある誤解（誤り）: ズレたら計画ファイルを削除して計画なしで進める / 計画は最初に作ったものを絶対に変えない / ズレは気にせず記憶だけで進める

### 要点5
- 問い: H1の/goalに対して、H2のPLAN.mdが担う役割はどれ？
- 正解: 数日〜数週間の仕事をセッションをまたいで進める、長期戦の型を作る
- 解説: /goalがひと晩の走りなら、PLAN.mdは数週間の旅の支度だよ。セッションをまたいでも現在地を見失わない。長い仕事ほど、この型が効いてくるね。
- よくある誤解（誤り）: /goalの上位互換で、以後/goalは不要になる / 1回のセッションを速くするための時短術である / AIの回答の文字数を制限する仕組みである

## 実践ミッション
進行中の中期案件を1つ選んでフェーズ分け・完了条件・現在地チェック欄入りのPLAN.mdをAIと作り、2回のセッションでPLAN.mdを読ませてから続きを進めます。

- 提出する証拠: 作成したPLAN.mdの内容と、2回目のセッションで現在地を確認して作業を続けた画面のスクリーンショット。案件名・取引先名など社外秘はマスクして構いません。

# H3 Computer UseでGUI操作を自動化

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: Computer Useとはどんな機能？
- 正解: AIが画面を見て、マウスとキーボードで人間と同じように操作する機能
- 解説: ホウ、AIが画面を「見て」、マウスとキーボードで動かすんだよ。人間と同じ方法で操作できるということだね。目と手を持ったAI、と覚えるといい。
- よくある誤解（誤り）: PCの部品を自動で交換する機能 / 画面の明るさを自動調整する機能 / キーボードの入力速度を上げる機能

### 要点2
- 問い: Computer Useが「最後の切り札」と呼ばれる理由はどれ？
- 正解: APIや連携機能がないアプリでも、原理上あらゆるソフトが自動化対象になるから
- 解説: 連携の窓口がないアプリでも、画面さえあれば操作できる。人間と同じ方法だから、原理上どんなソフトも対象になるんだよ。だから切り札、なんだね。
- よくある誤解（誤り）: 他のどの機能よりも動作が速いから / 一度設定すれば二度と失敗しないから / 無料で使える唯一の機能だから

### 要点3
- 問い: Computer Useを使ってはいけない場面として、このマスで示されているのはどれ？
- 正解: お金・送信・削除が絡む画面
- 解説: ここは大事なところだよ。お金の支払い、メールの送信、データの削除——戻れない操作が絡む画面では使わないこと。便利さより先に、安全の線引きだね。
- よくある誤解（誤り）: 文字が小さい画面 / 英語表記の画面 / 起動に時間がかかるアプリの画面

### 要点4
- 問い: 「速いが確実ではない」という特性へのつきあい方として正しいのはどれ？
- 正解: 最初は「1操作ずつ宣言→実行」の形で動かして観察する
- 解説: 初めは「次に何をするか宣言してから動いて」と頼み、一手ずつ観察するんだよ。相手の癖がわかってから任せる範囲を広げる。ホウ、あわてないのが賢者の順序だね。
- よくある誤解（誤り）: 確実でないなら一切使わない / 失敗してもよいので最速で全部任せる / エラーが出たらすぐPCを再起動する

### 要点5
- 問い: プロンプト例「この会計ソフトの画面で、一覧画面を開いて今月分をCSVエクスポートして」に添えられている指示はどれ？
- 正解: 「各操作の前に何をするか宣言してから動いて」
- 解説: 宣言してから動いてもらえば、あなたはAIの手元をずっと見ていられる。おかしな動きがあればすぐ止められるからね。見える化は、任せるための準備だよ。
- よくある誤解（誤り）: 「できるだけ速く終わらせて」 / 「途中経過は報告しなくていい」 / 「エラーが出たら自己判断で設定を変えて」

## 実践ミッション
普段使うアプリの定型操作を1つ選び、「各操作の前に何をするか宣言してから動いて」と添えてComputer Useに実行させます（お金・送信・削除が絡む画面は避けます）。

- 提出する証拠: AIが操作内容を宣言しながら実行している様子が分かるスクリーンショット。画面内の業務データや個人情報はマスクして共有していただいて構いません。

# H4 社内システムの転記を自動化

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: H4で自動化する対象として、このマスに沿うのはどれ？
- 正解: API連携できない社内システムや古い業務ソフトへの転記・定型入力
- 解説: 多くの会社でいちばん時間を食っているのは、システムの隙間の手作業なんだよ。Excelから社内システムへの転記のようなね。そこをComputer Useで埋めるのがこのマスだよ。
- よくある誤解（誤り）: 最新のクラウドサービス同士のAPI連携 / PCの初期セットアップ / SNSのデザイン制作

### 要点2
- 問い: プロンプト例に含まれている記録の指示はどれ？
- 正解: 「1件ごとに登録結果をスクショで記録して、最後に成功/失敗の一覧表を出して」
- 解説: 1件ごとの記録と、最後の成功/失敗一覧。この2つがあれば、あとから人間が確かめられるね。任せっぱなしにしない、それが実務で使える自動化だよ。
- よくある誤解（誤り）: 「作業が全部終わったら一言だけ報告して」 / 「記録は不要なので黙って進めて」 / 「1時間ごとに休憩を取って」

### 要点3
- 問い: 途中でエラーになって中途半端に終わる、というつまずきへの対処はどれ？
- 正解: 「失敗時は飛ばして続行、最後にまとめて報告」の指示を必ず入れる
- 解説: 1件つまずくたびに止まっていては、夜が明けてしまうからね。失敗は飛ばして続行、最後にまとめて報告。ホウ、失敗の扱い方まで先に決めておくのが設計だよ。
- よくある誤解（誤り）: エラーが出ないよう件数を1件だけにする / エラーが出たら最初から全部やり直させる / エラー表示を非表示に設定する

### 要点4
- 問い: H4のような実戦でもH3と同じく守るべき安全ルールはどれ？
- 正解: お金の支払い・送信・削除が絡む画面ではComputer Useを使わない
- 解説: 実戦になっても線引きは変わらないよ。お金・送信・削除の画面には使わない。転記や入力のような、確かめ直せる作業から任せていくのが正しい順番だね。
- よくある誤解（誤り）: 夜間は必ずPCの電源を切る / 社内システムには一切AIを近づけない / スクショは撮らないようにする

### 要点5
- 問い: H3とH4の関係として正しいのはどれ？
- 正解: H3で学んだComputer Useを、実際の社内業務に使うH3の実戦編がH4である
- 解説: H3で目と手の使い方を覚え、H4でいよいよ実務に放つ。素振りのあとの試合、というところだね。順番どおりに進めば怖くないよ。
- よくある誤解（誤り）: H4はH3とは無関係の別機能を学ぶマスである / H3が実戦編で、H4が基礎編である / H4を先に終えればH3は不要である

## 実践ミッション
転記系の手作業（例：Excelの一覧から社内システムへの入力）を1つ選び、「1件ごとに結果を記録」「失敗時は飛ばして続行し最後にまとめて報告」の指示つきで自動化して完走させます。

- 提出する証拠: 実行ログや成功/失敗の一覧表が分かるスクリーンショット。顧客名・金額・社内システムの画面など社外秘の部分はマスクしてください。

# H5 Codex Mobileで外出先から監視・承認

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: Codex Mobileでできることとして、このマスに沿うのはどれ？
- 正解: 外出先からスマホで、自宅・会社PCのエージェントを監視し、承認に応答し、指示を出す
- 解説: 働くのはPC側のエージェント、あなたはスマホから見守って、承認して、指示を出すんだよ。手のひらに小さな司令室を持つようなものだね。
- よくある誤解（誤り）: スマホ単体でPCと同じ作業をすべて行う / スマホの写真を自動で整理する / PCの電源を物理的に入れる

### 要点2
- 問い: スマホから送る指示の例として、このマスのプロンプト例に沿うのはどれ？
- 正解: 「承認待ちの内容を見せて。OK、実行して」
- 解説: 状況を聞く、承認待ちに応える、帰るまでの追加の仕事を頼む。この3つが外出先での基本の型だよ。移動時間が、指示を出す時間に変わるね。
- よくある誤解（誤り）: 「PCのOSを再インストールして」 / 「私のスマホの機種変更をして」 / 「画面の壁紙を変えて」

### 要点3
- 問い: 「外から指示したのにPCが動いていなかった」というつまずきへの対処はどれ？
- 正解: PCのスリープ設定を見直し、常時稼働できる環境を先に整える
- 解説: ホウ、留守番役が眠っていては号令も届かないからね。先にPCのスリープ設定を見直して、起きていられる環境を整えるんだよ。仕組みは足元からだね。
- よくある誤解（誤り）: 指示を送る回数を増やす / スマホを買い替える / PC側は諦めてスマホだけで作業する

### 要点4
- 問い: H5によって手に入る状態として、このマスに沿うのはどれ？
- 正解: 「PCの前にいる時間」と「AIが働く時間」が切り離された状態
- 解説: あなたが席を離れても、AIの仕事は止まらない。いる場所と働く時間が切り離される、これがこのマスの果実だよ。外の空気を吸いながら、仕事は進むんだね。
- よくある誤解（誤り）: PCが不要になり、すべてスマホで完結する状態 / 常にPCの画面を見張り続ける状態 / 外出そのものが不要になる状態

### 要点5
- 問い: 実践課題「外出先から承認または新規指示を1回行う」の狙いはどれ？
- 正解: 遠くからでも仕事を動かせる、という体験を一度実際に味わうこと
- 解説: 一度でも「外から仕事が動いた」を体験すると、働き方の景色が変わるんだよ。小さな承認ひとつでいい。まず翼を広げてごらん、だね。
- よくある誤解（誤り）: スマホの操作速度を鍛えること / 外出の予定を増やすこと / PCを使わない日を作ること

## 実践ミッション

- 提出する証拠: スマホ側の承認・指示画面と、PC側で仕事が進んだ結果が分かるスクリーンショット。指示内容に業務上の機密が含まれる場合はマスクして構いません。

# H6 複数エージェントをスマホで統括

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: H6で学ぶ内容として正しいのはどれ？
- 正解: 複数のPC・複数のエージェントを走らせ、スマホ1台から全体を統括する運用
- 解説: 働き手が複数になったら、次は率い方を学ぶ番だよ。スマホ1台で全体を見渡す、一人司令官の運用だね。ホウ、ずいぶん遠くまで来たものだよ。
- よくある誤解（誤り）: 1台のPCの動作を速くするチューニング / スマホを2台持ちにする方法 / エージェントを1つに減らしてシンプルにする方法

### 要点2
- 問い: 複数エージェントの割り当てで設計すべきこととして、このマスに沿うのはどれ？
- 正解: 「どの機体に・どの仕事を・どの権限で」を割り当てる
- 解説: 誰に・何を・どこまで任せるか。人の組織づくりと同じだね。特に「どの権限で」を決めておくと、任せても危なくない部隊になるよ。
- よくある誤解（誤り）: どの機体の色をどれにするか / どのエージェントに名前をつけるか / どの時間に全員を休ませるか

### 要点3
- 問い: 「全部を細かく見ようとしてパンクする」というつまずきへの対処はどれ？
- 正解: 「異常があるものだけ報告」の例外管理に切り替え、正常は見ない
- 解説: 全部を見ようとすると、率いる側が先に倒れてしまうからね。正常は見ない、異常だけ聞く。手放す勇気が、統括のコツだよ。
- よくある誤解（誤り）: 監視する時間を倍に増やす / エージェントを1つに減らす / 報告をすべて印刷して読む

### 要点4
- 問い: このマスのプロンプト例に沿った報告のさせ方はどれ？
- 正解: 「それぞれの今日の状況をまとめて報告して。異常があるものだけ詳しく」
- 解説: まとめの報告と、異常だけの詳細。この二段構えなら、短い時間で全体がつかめるね。報告の形を決めるのも、司令官の仕事だよ。
- よくある誤解（誤り）: 「全エージェントの全ログを毎時間送って」 / 「報告は月に1回だけまとめて」 / 「良い報告だけ聞かせて」

### 要点5
- 問い: H5とH6の関係として正しいのはどれ？
- 正解: H5が1台のPCの遠隔操作、H6はそれを複数のPC・エージェントの統括へ広げる段階である
- 解説: H5で1羽を遠くから見守れるようになり、H6では群れ全体を率いる。1対1から1対多へ、だね。土台は同じ、視野が広がるんだよ。
- よくある誤解（誤り）: H6はH5より簡単な入門マスである / H5とH6は同じ内容の繰り返しである / H6ではスマホを使わなくなる

## 実践ミッション
2つ以上のエージェント（またはタスク系統）を動かし、スマホから「それぞれの状況をまとめて報告、異常があるものだけ詳しく」の形式で統括報告をさせます。

- 提出する証拠: 複数のエージェント（タスク系統）の統括報告が分かるスクリーンショット。担当業務名や社外秘の内容はマスクして共有していただいて構いません。

# H7 自分専用Business OSの構築

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: 「Business OS」とは何か、このマスに沿う説明はどれ？
- 正解: ここまでの63マスの部品を1枚の地図に統合した、自分の事業がAIの上で回る仕組み
- 解説: GPTsも自動化も連携も自律ループも、ぜんぶ部品だったんだよ。それを1枚の地図に組み上げたものがBusiness OS。あなたの事業がAIの上で回る仕組み、だね。
- よくある誤解（誤り）: PCにインストールする新しい基本ソフト / 会計専用の市販パッケージソフト / AIが自動で作る会社のロゴ

### 要点2
- 問い: プロンプト例にある業務棚卸しの分類はどれ？
- 正解: ①すでにAI化済み ②すぐAI化できる ③人間がやるべき、の3分類
- 解説: 済んだもの、すぐできるもの、人がやるべきもの。この3つに分けると、次に何をAIへ渡すかが一目で見えるんだよ。棚卸しは設計の第一歩だね。
- よくある誤解（誤り）: ①好きな仕事 ②嫌いな仕事 ③どちらでもない仕事 / ①午前の仕事 ②午後の仕事 ③夜の仕事 / ①社内の仕事 ②社外の仕事 ③保留の仕事

### 要点3
- 問い: 「理想の全体像を描いて終わる」というつまずきへの対処はどれ？
- 正解: 構成図の中の「次の1本」を決めて即着手する
- 解説: 地図は眺めるためでなく、歩くためにあるんだよ。次の1本を決めて、すぐ着手。OSは運用しながら育てるものだからね。
- よくある誤解（誤り）: 構成図をもっと美しく描き直す / 全体像は描かず思いつきで進める / 全部を一気に実装するまで寝ない

### 要点4
- 問い: H7が示す、あなた自身の立ち位置の変化はどれ？
- 正解: 労働者から、仕組みの設計者・経営者へ変わる
- 解説: 手を動かす人から、仕組みを設計する人へ。ホウ、これがこの64マスの旅が目指してきた変化だよ。あなたの時間は、判断と創造のために使うんだね。
- よくある誤解（誤り）: 作業者として今まで以上に手を速く動かす / AIの下請けとして働くようになる / すべての判断をAIに譲る

### 要点5
- 問い: 「②すぐAI化できる」業務に対して、プロンプト例で作らせるものはどれ？
- 正解: 移行計画と、事業全体のBusiness OS構成図
- 解説: 「すぐできる」を、いつ・どの順で移すかの計画に落とし、全体の構成図とセットで持つんだよ。計画と地図がそろえば、あとは1本ずつ実装するだけだね。
- よくある誤解（誤り）: AI化を諦める理由のリスト / 業務を廃止する社内通知 / 新しい人材の採用計画

## 実践ミッション
自分の業務全体をAIに棚卸しさせて「AI化済み／すぐAI化できる／人間がやるべき」に分類し、Business OS構成図を完成させたうえで、未実装の「次の1本」を決めて着手します。

- 提出する証拠: 完成したBusiness OS構成図と、着手した「次の1本」が分かるスクリーンショット。事業内容のうち社外秘にあたる部分はマスクして構いません。

# H8 最終課題：完全自動運用システム

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: 最終課題H8で完成させるものはどれ？
- 正解: 「リサーチ→制作→承認→公開→報告」が毎週回る自動運用システムと、1週間の無人運転
- 解説: 最終試験だよ。人間が指示しなくても1週間、リサーチから報告までが自分で回る仕組みを完成させる。題材はSNS運用でもレポート業務でも、あなたの事業に合うものでいいんだよ。
- よくある誤解（誤り）: AIについての感想文 / 新しいPCの購入計画 / 64マスすべてのクイズの復習ノート

### 要点2
- 問い: プロンプト例の/goalに入っている大切な制約はどれ？
- 正解: 「公開・送信前は必ず私の承認を取ること」
- 解説: 完全自動でも、世に出る一歩手前には人の承認を挟むんだよ。自律と安全は両立させるもの、だね。この一文があなたと事業を守ってくれるよ。
- よくある誤解（誤り）: 「承認は一切不要、全部自動でやること」 / 「毎日深夜3時に必ず報告すること」 / 「失敗したらすぐシステムを削除すること」

### 要点3
- 問い: 「欲張って複数システムを同時に作る」というつまずきへの対処はどれ？
- 正解: まず1本を完璧に回す。2本目からは半分の時間で作れる
- 解説: 1本目は学びの塊だから、じっくり完璧に回すんだよ。1本回れば型が手に入り、2本目からは半分の時間で作れる。急がば回れ、だね。
- よくある誤解（誤り）: 3本同時に作って早いものを採用する / システムづくりは外注する / 完成をあきらめて手作業に戻る

### 要点4
- 問い: H8で統合する、ここまでの旅で学んだ要素の組み合わせとして正しいのはどれ？
- 正解: /goal・定期実行・MCP連携・承認フロー・Mobile監視といった全機能の統合
- 解説: 振り返ってごらん。自律の/goal、時を刻む定期実行、道具をつなぐMCP、安全を守る承認フロー、外から見守るMobile。旅で拾ってきた石がぜんぶ、この一つのアーチに収まるんだよ。
- よくある誤解（誤り）: /goalだけを単独で使う / Computer Useだけをひたすら使う / 手作業とメモ帳だけで運用する

### 要点5
- 問い: この最終課題を成し遂げた者に与えられる称号はどれ？
- 正解: 「チャッピーの親友」
- 解説: 1週間の無人運転を成し遂げた者だけが、チャッピーの親友を名乗れるんだよ。その手にはもう、チャッピーの親友の証がある。ホウ、静かに誇っていい旅だったね。
- よくある誤解（誤り）: 「プロンプトの達人」 / 「タイピングマスター」 / 「フォルダ整理王」

## 実践ミッション
題材を1つ選び（SNS運用・レポート業務など自由）、「公開・送信前は必ず承認を取る」制約つきの週次自動運用システムを完成させて、1週間の運用実績を報告書にまとめます。

- 提出する証拠: システムの構成（/goal指示文や構成図）と、1週間分の実行報告・運用報告書が分かるスクリーンショット。公開前の情報・顧客名・数値など社外秘はマスクしてください。
