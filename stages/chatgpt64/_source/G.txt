# G1 MCPの基礎知識と概念

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: MCP（Model Context Protocol）とは、ひとことで言うと何？
- 正解: AIと外部ツールをつなぐための共通規格
- 解説: MCPはね、AIと外部ツールをつなぐ共通規格のことだよ〜。これがあるから、いろんな道具に手を伸ばせるようになるんだ。8本の足で一気につなぐ、その土台になる決まりごとなんだよ〜。
- よくある誤解（誤り）: 画像を高速で生成するための新しいAIモデル / パソコンの動作を速くするためのメモリ管理技術 / SNSの投稿を予約するためのカレンダー機能

### 要点2
- 問い: MCPのイメージとして、このマスで使われている例えはどれ？
- 正解: 「AI用のUSBポート」——対応ツールなら何でも挿して使える
- 解説: そうそう、「AI用のUSBポート」だよ〜。対応している道具なら何でも挿して使える、便利な差し込み口なんだね〜。この絵が頭にあると、あとの連携がすんなり分かるよ。
- よくある誤解（誤り）: 「AI用の金庫」——大事なデータを鍵をかけてしまっておける / 「AI用の翻訳機」——外国語のサイトを日本語にしてくれる / 「AI用のカメラ」——画面の中身を写真に撮ってくれる

### 要点3
- 問い: MCPという横文字に圧倒されてしまったとき、どう理解して前に進めばいい？
- 正解: 「AIがGmailやSlackを直接触れるようになる差し込み口」とだけ理解する
- 解説: むずかしく考えなくて大丈夫だよ〜。「AIがGmailやSlackを直接触れるようになる差し込み口」——これだけ分かれば前に進めるんだ。細かいことは、使いながらゆっくり覚えればいいんだよ〜。
- よくある誤解（誤り）: 全部の技術仕様を暗記してから次に進む / プログラミングを先に習得してから戻ってくる / 理解できないので、このステージは飛ばしてしまう

### 要点4
- 問い: MCPの概念を学ぶプロンプトとして、このマスの例に沿っているのはどれ？
- 正解: 「MCPとは何か、家電とコンセントの例えで説明して。私が使っているツールはMCP対応している？」
- 解説: 身近な例えでお願いするのがコツだよ〜。家電とコンセントの例えなら、すっと頭に入るよね〜。ついでに自分の使っているツールが対応しているかも聞いちゃえば、一石二鳥なんだ。
- よくある誤解（誤り）: 「MCPの技術仕様書を英語の原文のまま全部見せて」 / 「MCPを使わずに済む方法だけを教えて」 / 「MCPのプログラムコードを今すぐ書いて」

### 要点5
- 問い: G1がステージGの最初に置かれている理由はどれ？
- 正解: MCPの仕組みを知ると、以降の連携の全体像が一気に見通せるから
- 解説: 最初に地図を広げておくと、旅がぐっと楽になるんだよ〜。MCPの仕組みが分かれば、この先の連携の全体像がぱっと見通せるんだ。あわてず、ここから一歩ずつ行こうね〜。
- よくある誤解（誤り）: G1が終わればもう他のマスをやる必要がないから / 一番むずかしい内容を最初に済ませるべきだから / MCPは概念だけ知れば実際に使うことはないから

## 実践ミッション
自分が日常で使っているツール（メール・チャット・クラウドストレージなど）のうち、MCP連携できるものをAIに調べてもらいながら3つ挙げてリストにします。

# G2 外部ツールとのMCP連携設定

### 要点1
- 問い: G2で実際に行うことはどれ？
- 正解: Google Drive・Slack・GmailなどをMCPで接続し、認証と権限の付与を行う
- 解説: ここでいよいよ、DriveやSlack、Gmailを実際につないでいくんだよ〜。認証して、どこまで触っていいか権限を決めてあげるの。つながった瞬間、AIの守備範囲がPCの外まで広がるんだ〜。
- よくある誤解（誤り）: 新しいSNSアカウントをたくさん作る / パソコンを初期化して環境を作り直す / MCPの解説記事を読んで感想文を書く

### 要点2
- 問い: 接続のとき権限を求められて不安になったら、どうするのがいい？
- 正解: 読み取り権限から始めて、送信・削除系は必要になってから付与する
- 解説: 最初は読み取り権限だけでいいんだよ〜。送信や削除の権限は、必要になったときに足せば大丈夫。少しずつ手をつないでいくのが、安心のコツなんだね〜。
- よくある誤解（誤り）: 不安なので接続自体をあきらめる / 何も考えず全部の権限を許可する / 他人のアカウントで代わりに試す

### 要点3
- 問い: 接続後に試すプロンプトとして、このマスの例に沿っているのはどれ？
- 正解: 「Gmailの未読から、返信が必要なものだけ抽出して」
- 解説: まずは「未読から返信が必要なものだけ抽出して」みたいな、読み取り系のお願いから始めようね〜。眺めるだけなら失敗しても怖くないでしょ〜。ここで成功体験をひとつ作るのが大事なんだ。
- よくある誤解（誤り）: 「Gmailの全メールを今すぐ削除して」 / 「Slackの全メンバーに一斉メッセージを送って」 / 「Driveのファイルを全部ダウンロードして公開して」

### 要点4
- 問い: G2で学ぶ「安全設計」の考え方はどれ？
- 正解: 「AIにどこまで触らせるか」の範囲をあらかじめ決めておくこと
- 解説: 大事なのは「どこまで触らせるか」を先に決めておくことだよ〜。ぜんぶ任せるでも、ぜんぶ禁止でもなくて、ちょうどいい範囲を自分で設計するの。それが安心して任せる第一歩なんだね〜。
- よくある誤解（誤り）: セキュリティソフトを何本も入れること / パスワードを毎日変更すること / AIには絶対に何も触らせないこと

### 要点5
- 問い: 外部ツールがMCPでつながると、何が変わる？
- 正解: AIの守備範囲がPCの外のツールにまで広がる
- 解説: つながった瞬間、AIの手が届く範囲がPCの外まで広がるんだよ〜。GmailもDriveもSlackも、コピペで運ばなくてよくなるの。8本の足がそれぞれの道具に届く感じ、気持ちいいよ〜。
- よくある誤解（誤り）: パソコンの動作速度が2倍になる / 月額料金が自動的に安くなる / インターネットなしでもツールが使えるようになる

## 実践ミッション

- よくある誤解（誤り）: 出力先→AI処理→トリガー / AI処理→AI処理→AI処理 / トリガー→出力先→AI処理

- 解説: 欲張らずに、ノード3つの最小構成から始めるのがコツだよ〜。受け取る→AI→送る、これだけでちゃんと動くの。足は8本あっても、最初は3本から動かすんだよ〜。

- 解説: 問い合わせが入る→AIが返信案を作る→Slackの承認チャンネルに投げる、という流れだよ〜。構成図と設定手順までAIに出してもらえば、初めてでも迷わないの。頼り上手が上達の近道だよ〜。

- 解説: リサーチ→本文→画像→予約投稿まで、ぜんぶひとつのラインにするんだよ〜。ステージCで学んだコンテンツ制作と、ステージGの自動化の合体技なの。流れ作業になると、続けるのがぐっと楽になるよ〜。

### 要点2

- 解説: いちばん大事なのがここ！投稿前に人間が承認する「関所」を必ず設けるんだよ〜。世に出る前に、あなたの目でひと目確認する場所を作っておくの。これだけは省略しちゃだめだよ〜。

- 解説: 承認を挟むのは手抜きじゃなくて、ちゃんとした「設計」なんだよ〜。全自動投稿で事故ってからでは遅いの。炎上のリスクは、この関所で消しておくんだね〜。
- よくある誤解（誤り）: 自動化の意味がなくなるので入れないほうがいい / AIの性能が低いときだけ入れる応急処置である / 承認は月に1回まとめてやれば十分である

- 解説: ステージCのコンテンツ制作と、ステージGの自動化の合体技だよ〜。作る力と流す力、両方そろって初めて自動運用になるの。今までの学びが手をつなぐ瞬間だね〜。
- よくある誤解（誤り）: ステージA（基本操作）×ステージB（日常業務） / ステージD（データ分析）×ステージE（開発） / ステージF（チーム連携）×ステージH（自律化）

### 要点5

- 正解: ①トレンドリサーチ ②本文と画像生成 ③下書きを私に承認依頼 ④承認後に予約投稿
- 解説: リサーチ→生成→承認依頼→承認後に予約投稿、の順だよ〜。「承認してから投稿」の順番が崩れないことが何より大事なの。ラインの並び、しっかり覚えておこうね〜。

- 問い: 定期実行タスクを設定するとき、必ずセットで設定すべきものはどれ？
- 正解: 「失敗したら必ず通知」の設定
- 解説: 「失敗したら必ず通知」を必ずセットにするんだよ〜。いちばん怖いのは、失敗に気づかないまま放置される「無音の失敗」なの。転んだら教えてね、って先に約束しておこうね〜。
- よくある誤解（誤り）: 実行結果を毎回印刷する設定 / 深夜にもう一度実行する設定 / 実行のたびにパスワードを変える設定

### 要点4
- 問い: G6で自動化の対象にしていく仕事はどれ？
- 正解: 毎朝のデータ集計・ファイル整理・バックアップなど「私がやらなくても回る仕事」
- 解説: 狙い目は、毎日くり返す「私がやらなくても回る仕事」だよ〜。集計、整理、バックアップ——1つずつ手放していくの。空いた手で、あなたにしかできない仕事をしようね〜。
- よくある誤解（誤り）: 一生に一度しかやらない特別な仕事 / その場の判断が毎回必要な交渉ごと / お客様と直接顔を合わせる接客

### 要点5
- 問い: G6の実践課題として正しいのはどれ？
- 正解: 毎日の定期実行タスクを1本設定し、3日連続で成功させる
- 解説: 課題は、定期実行タスクを1本設定して、3日連続で成功させることだよ〜。1回動くのと、毎日ちゃんと回るのは別ものなの。3日続いたら、それはもう立派な仕組みだね〜。
- よくある誤解（誤り）: タスクを設定だけして実行はしない / 10本のタスクを一気に設定する / 手動実行を3日続けてから考える

## 実践ミッション

# G7 チームでのプラグイン・MCP共有と管理

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: G7で防ごうとしている「属人化」とはどんな状態？
- 正解: 作った人しか直せない状態
- 解説: 「作った人しか直せない」状態が属人化だよ〜。作った人がお休みしたら止まっちゃう仕組みは、ちょっと危ういの。みんなで支えられる形にしておくのが、このマスの目当てなんだ〜。
- よくある誤解（誤り）: チーム全員が同じ作業をしている状態 / 誰も自動化を使っていない状態 / AIが人の代わりに雇われている状態

### 要点2
- 問い: 自分の環境依存で他の人が動かせないとき、最短の対処はどれ？
- 正解: 手順書はAIに書かせて、別の1人に試してもらう
- 解説: 手順書はAIに書かせて、別の1人に試してもらうのが最短だよ〜。自分では気づけない「うちの環境だけの前提」を、他の人が見つけてくれるの。テスターさんは宝物だね〜。
- よくある誤解（誤り）: 他の人のPCを自分と同じ機種に買い替えてもらう / 自分が全員のPCで代わりに設定して回る / 共有をあきらめて自分だけで使い続ける

### 要点3
- 問い: このマスのプロンプト例として正しいのはどれ？
- 正解: 「この自動化設定をチームメンバーが再現するためのセットアップ手順書を作って。つまずきそうな箇所に注意書きを入れて」
- 解説: 再現用の手順書を作ってもらって、つまずきそうな箇所に注意書きまで入れてもらうんだよ〜。読む人の目線で先回りしておくと、質問の嵐にならずに済むの。世話焼きの極意だね〜。
- よくある誤解（誤り）: 「この自動化設定を誰にも真似できないように暗号化して」 / 「チームメンバーの評価レポートを作って」 / 「自動化の説明は口頭で済ませたいので要点だけ暗記させて」

### 要点4
- 問い: G7で学ぶ内容の組み合わせとして正しいのはどれ？
- 正解: MCPサーバー・設定の共有方法と、権限・アカウントの管理
- 解説: MCPサーバーや設定をどう共有するか、権限やアカウントをどう管理するか——この2本立てだよ〜。便利さと安全、8本の足で両方ちゃんと持つの。チーム展開の基本セットだね〜。
- よくある誤解（誤り）: 画像生成のコツとSNSのバズらせ方 / パソコンの分解と修理の方法 / 経理ソフトの仕訳入力の方法

### 要点5
- 問い: G7の実践課題として正しいのはどれ？
- 正解: 自分の自動化1本を、他の人が再現できる手順書つきで共有する
- 解説: 自分の自動化を1本、手順書つきでチームに共有するのが課題だよ〜。あなたの便利が、みんなの便利になる瞬間なの。おすそ分けって、いいものだよね〜。
- よくある誤解（誤り）: チーム全員分の自動化を自分ひとりで作る / 自動化の存在をチームに秘密にしておく / 手順書だけ作って共有はしない

## 実践ミッション

# G8 ブラウザ操作自動化で競合調査

## このマスで押さえる要点（理解度テストの正解と解説）

### 要点1
- 問い: G8でCodexにやらせることはどれ？
- 正解: Webブラウザを操作させ、競合サイトの巡回・価格チェック・情報収集を自動化すること
- 解説: ブラウザをAIに操作してもらって、競合サイトの巡回や価格チェックを自動化するんだよ〜。毎週手作業で見て回っていた調査が、勝手に回るようになるの。目が8個あるみたいで頼もしいよ〜。
- よくある誤解（誤り）: 競合他社のサイトを改ざんすること / 自社サイトのデザインを自動で変更すること / 競合のSNSアカウントに自動でコメントすること

### 要点2
- 問い: データ取得先のルールについて、正しい心がけはどれ？
- 正解: 会員制サイトの規約・robots・アクセス頻度を確認し、「人が見てよい頻度」を超えない
- 解説: ここがいちばん大事なところだよ〜。会員制サイトの規約やrobots、アクセス頻度をちゃんと確認して、「人が見てよい頻度」を超えないこと。マナーを守ってこそ、安心して続けられる調査になるんだね〜。
- よくある誤解（誤り）: 自動化なのでルールは気にせず高速で巡回してよい / 取得がバレなければ規約は守らなくてよい / アクセス頻度は多ければ多いほどよい

### 要点3
- 問い: このマスのプロンプト例として正しいのはどれ？
- 正解: 「競合3社の料金ページを巡回して、価格・プラン内容を表に整理して。前回チェック時から変わった箇所があれば強調して」
- 解説: 料金ページを巡回して表に整理、変わった箇所は強調——これがお手本のプロンプトだよ〜。丸ごとコピーや毎秒アクセスは、マナー違反になっちゃうからだめだよ〜。ほどほどが上手なつきあい方なの。
- よくある誤解（誤り）: 「競合サイトのデータを全ページ丸ごとコピーして保存して」 / 「競合サイトに毎秒アクセスして最新情報を取り続けて」 / 「競合サイトの会員ページにログインして中の情報を取ってきて」

### 要点4
- 問い: G8で取得データとセットで仕組み化するものはどれ？
- 正解: 取得データの整理と、変化の検知（差分検知）
- 解説: 取ってくるだけじゃなくて、整理して、前回からの変化を検知するところまでセットにするんだよ〜。「どこが変わったか」だけ教えてもらえたら、見る時間はほんの少しで済むの。賢い手抜きだね〜。
- よくある誤解（誤り）: データの完全削除機能 / データの印刷と郵送 / データの暗号化と隠蔽

### 要点5
- 問い: G8の実践課題として正しいのはどれ？
- 正解: 競合ウォッチの自動巡回を1本作り、週次で差分レポートを受け取る
- 解説: 競合ウォッチの自動巡回を1本作って、週に1回、差分レポートを受け取るのが課題だよ〜。週次くらいの、ゆったりした頻度がちょうどいいの。無理なく長く、が調査のコツだね〜。
- よくある誤解（誤り）: 競合サイトを1日100回チェックする仕組みを作る / 競合の情報を自社サイトにそのまま転載する / 調査は自動化せず毎日手作業で続ける

## 実践ミッション
競合サイトの規約やアクセス頻度のマナーを確認したうえで、競合ウォッチの自動巡回を1本作り、週次の差分レポートを1回受け取ります。

- 提出する証拠: 自動巡回の設定・指示内容と、受け取った差分レポートのスクリーンショット。調査対象の社名や具体的な価格情報など、共有しづらい部分はマスクしていただいて構いません。
